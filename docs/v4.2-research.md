# v4.2 Research — Adopting Tremor charts in Conan

Date: 2026-05-27. Scope: evaluate the Tremor charting library for replacing
Conan's two hand-rolled SVG charts — `ui/src/components/PulseChart.tsx` (stacked
area) and the Context `Ring` donut/gauge in `ui/src/components/Widgets.tsx`.

## Bottom line (read this first)

Tremor is a **clean fit** here — but only via its **current "Tremor Raw"
copy-in model**, NOT the legacy `@tremor/react` npm package. Two facts make the
decision:

1. **Tailwind v4 is the deciding factor, and Tremor Raw is built _for_ v4.** The
   current Tremor docs state: *"Tremor Raw is designed for React v18.2.0+ and
   requires Tailwind CSS v4.0+."* (tremor.so/docs/getting-started/installation).
   That is exactly this repo's stack. The legacy `@tremor/react` npm package is
   the opposite — it needs a `tailwind.config.js` with a `content` glob into
   `node_modules/@tremor` plus a color **safelist**, none of which exists (or can
   cleanly exist) in our CSS-first `@import "tailwindcss"` + `@theme inline`
   setup. Community reports confirm `@tremor/react` does not render on Tailwind
   v4 (GitHub discussion tremorlabs/tremor-npm#1010). **Do not install
   `@tremor/react`.**

2. **Theming to our `--color-chart-*` tokens is a file-edit, not a fight.** In
   the copy-in model we own `lib/chartUtils.ts`, where color names map to
   Tailwind classes (`fill-blue-500`, `stroke-blue-500`, …). We replace those
   with arbitrary-value classes pointing at our CSS vars
   (`fill-[var(--color-chart-1)]`, …) so charts honor the existing emerald-
   anchored palette and the `.dark` toggle automatically.

**Caveat / honest flag:** the only real cost is a **bundle-size jump from
Recharts + d3** (Tremor charts are Recharts wrappers). Our charts today are
zero-dep. Recharts pulls in a chunk of `d3-*` modules (~tens of KB gzipped plus
Recharts itself, commonly cited around 100 KB+ gzipped for the lot). For a
desktop Tauri app served from a local sidecar this is acceptable, but it is the
one genuine downside versus the status quo. If you want charts to "just look
nicer / get tooltips/legends for free" it's worth it; if the hand-rolled SVGs are
fine, the cheapest path is to keep them.

Recommendation: **adopt Tremor Raw for the two charts** (gets us real tooltips,
legends, responsive container, accessibility, and a maintained API), wire colors
to our tokens via `chartUtils.ts`, and keep everything else hand-rolled. React 19
works (Recharts 2.x + Tremor Raw run on React 19 in practice; pin and verify on
`npm run build` — see flag in §3).

## 1. Distribution model (current, 2025–2026)

Tremor today ships **two parallel things**:

- **`@tremor/react` (legacy npm package)** — still on npm (300K+ monthly
  downloads, v3.18.x) and still promoted on the marketing site, but it is the
  **old** model: import components, configure via `tailwind.config.js` `content`
  glob into `node_modules/@tremor/**` + a `safelist` for dynamically-composed
  color classes. This is a **Tailwind v3 architecture** and is the wrong choice
  for us (see §2).
- **Tremor Raw (the current recommended path, "Copy & Paste React components")**
  — the shadcn-style model. You don't depend on a Tremor package; you **copy the
  component source into your repo** (e.g. `ui/src/components/AreaChart.tsx`,
  `ProgressCircle.tsx`) plus a couple of small util files (`lib/utils.ts` with a
  `cx` helper, `lib/chartUtils.ts` with the color map). The repo is
  `github.com/tremorlabs/tremor` (Apache-2.0, ~35+ components, built on Recharts
  + Radix UI + tailwind-variants). Components are added via a CLI or by literal
  copy-paste from the docs.

**What you install/add (Tremor Raw):** the runtime deps the chart components
import (`recharts`, plus `tailwind-variants` / `clsx` / `tailwind-merge` — we
already have `clsx` and `tailwind-merge` and a `cn()` helper), then paste the
specific component files you need. Nothing called "@tremor/*" ends up in
`package.json`.

**Maintenance status:** the legacy `@tremor/react` is effectively in
maintenance — the team's energy moved to Tremor Raw (and Tremor Blocks was
acquired by Vercel). A maintainer-adjacent comment in the Tailwind-v4 discussion
(2024-09-02) explicitly noted moving away from the npm package toward the Raw
version after it adopted Radix. **Treat `@tremor/react` as legacy; use Tremor
Raw.**

## 2. Tailwind v4 compatibility — THE critical question

- **Tremor Raw: YES, built for v4.** Official docs: *"requires Tailwind CSS
  v4.0+."* It uses the CSS-first setup — no `tailwind.config.js`, no `content`
  glob, no safelist. Because the component source lives in our own `ui/src/`,
  the normal Tailwind v4 content auto-detection already scans it; there is
  nothing to add to a config that doesn't exist. (If a class ever lived outside
  the scanned tree you'd add a `@source` directive in `index.css`, but for
  copied-in components that's unnecessary.)
- **`@tremor/react` (legacy): NO, not cleanly on v4.** It relies on the v3
  `content` glob into `node_modules/@tremor/**` and a `safelist` for its
  dynamically-built color classes (`bg-blue-500`, etc.). Tailwind v4 removed
  `tailwind.config.js` as the primary config surface and changed safelisting;
  users report charts/components simply **don't render** on v4.0.x with the npm
  package (tremorlabs/tremor-npm#1010, and tremor-blocks#2). Pinning Tailwind to
  v3.4 to use `@tremor/react` would mean **downgrading the whole UI off v4**,
  which contradicts the repo's CLAUDE.md stack — not an option.

**Verdict:** the only viable Tremor path on this repo is **Tremor Raw**. It is
not a workaround — it's the maintained, v4-native model. The hand-rolled SVG
fallback remains the no-new-deps alternative if we don't want Recharts.

## 3. Dependencies + bundle

- **Under the hood:** Tremor charts are **Recharts** wrappers (the docs' own
  source shows `PieChart as ReChartsDonutChart`, `ResponsiveContainer`, etc.).
  Recharts depends on a set of **`d3-*`** modules (scale, shape, array, etc.).
- **New runtime deps we'd add:** `recharts` (+ its transitive `d3-*`), and
  `tailwind-variants` (small). We already have `clsx` + `tailwind-merge` (the
  `cn`/`cx` helper) and `radix-ui` — so Radix is covered. `ProgressCircle` and
  `AreaChart` are the only two component files we need.
- **Bundle impact:** non-trivial. Recharts + d3 commonly lands around
  ~100 KB+ gzipped once tree-shaken to what AreaChart/DonutChart touch. Our
  current charts add **0 KB** of deps. For a local-sidecar Tauri desktop app
  this is acceptable, but it's the real trade-off — flag it to the user.
- **React 19:** Tremor Raw targets React 18.2+ and works with React 19 in
  practice (Recharts 2.x renders under React 19). **Uncertainty flag:** confirm
  no peer-dep warnings — install with the normal resolver first; if Recharts
  emits a React-19 peer warning, it's typically benign (`--legacy-peer-deps` not
  expected to be needed with npm's current resolver, but verify). Gate on
  `cd ui && npm run build` passing.

## 4. Theming to Conan's tokens (light default + `.dark`)

The repo defines the palette in `ui/src/index.css`:
`--chart-1..5` as raw hex for `:root` (light) and `.dark` (dark), exposed to
Tailwind as `--color-chart-1..5` via the `@theme inline` block. Today's
PulseChart maps category → `var(--color-chart-N)`.

Tremor's color system lives in **`lib/chartUtils.ts`** — a `chartColors` object
that maps a color name to four Tailwind classes per `ColorUtility`
(`bg | stroke | fill | text`), e.g. `blue → { fill: "fill-blue-500", stroke:
"stroke-blue-500", … }`. Chart components call `getColorClassName(color, util)`
to pick the class. Because **we own this file**, we override the entries to point
at our CSS vars using Tailwind arbitrary-value classes:

```ts
// ui/src/lib/chartUtils.ts (copied in, then edited)
export const chartColors = {
  chart1: { bg: "bg-[var(--color-chart-1)]", stroke: "stroke-[var(--color-chart-1)]",
            fill: "fill-[var(--color-chart-1)]", text: "text-[var(--color-chart-1)]" },
  chart2: { bg: "bg-[var(--color-chart-2)]", stroke: "stroke-[var(--color-chart-2)]",
            fill: "fill-[var(--color-chart-2)]", text: "text-[var(--color-chart-2)]" },
  chart3: { /* --color-chart-3 */ },
  chart4: { /* --color-chart-4 */ },
  chart5: { /* --color-chart-5 */ },
} as const satisfies Record<string, Record<ColorUtility, string>>;
export type AvailableChartColorsKeys = keyof typeof chartColors; // "chart1".."chart5"
```

Since the vars resolve differently under `:root` vs `.dark`, the **dark toggle
works automatically** — no second palette, no Tremor `color-scheme` plumbing.
For `ProgressCircle`, which is driven by a `variant` enum (`default | neutral |
warning | error | success`) rather than a free color, edit the component's
variant-class map (it's a `tailwind-variants` block in the copied file) so
`default` uses `text-[var(--color-chart-1)]` / our `--primary`, and `error`/
`warning` use the repo's `--destructive` / `bg-amber-*` to match the existing
Ring's `pct >= 80 → destructive` rule. Track and ring use
`text-muted-foreground/20` for the unfilled arc, matching the current SVG.

## 5. Concrete migration

### (a) PulseChart → Tremor `AreaChart` (stacked)

Tremor `AreaChart` wants **one flat object per x-tick** with the index key plus
one numeric field per category. Our `PulseSeries.buckets` (`usePulse.ts`) are
`{ t, events, types: Record<PulseCategory, number>, retries, tokens, cost }`.
Reshape buckets → flat rows, mapping the 5 categories onto our `chartN` colors:

```tsx
import { AreaChart } from "../components/AreaChart"; // copied-in Tremor Raw

const CAT = [
  { key: "tool", label: "Tools", color: "chart1" },
  { key: "assistant", label: "Assistant", color: "chart2" },
  { key: "prompt", label: "Prompts", color: "chart3" },
  { key: "session", label: "Session", color: "chart4" },
  { key: "other", label: "Other", color: "chart5" },
] as const;

const data = (series?.buckets ?? []).map((b) => ({
  t: new Date(b.t).toLocaleTimeString([], { hour: "2-digit", minute: "2-digit" }),
  Tools: b.types?.tool ?? 0,
  Assistant: b.types?.assistant ?? 0,
  Prompts: b.types?.prompt ?? 0,
  Session: b.types?.session ?? 0,
  Other: b.types?.other ?? 0,
}));

<AreaChart
  className="h-24"                 // compact strip height (~plotH today)
  data={data}
  index="t"
  categories={["Tools", "Assistant", "Prompts", "Session", "Other"]}
  colors={["chart1", "chart2", "chart3", "chart4", "chart5"]}
  type="stacked"
  showLegend={false}              // keep our own footer legend, or set true
  showYAxis={false}
/>
```

Notes / gaps to preserve:
- **Token overlay line + api_retry red ticks** are NOT first-class in Tremor's
  AreaChart. Options: (i) keep them as a thin hand-rolled SVG overlay layered on
  top (cheapest — we already have the geometry), or (ii) drop them, or (iii) use
  a Recharts `ComposedChart` directly. Recommend **(i)** — Tremor for the stacked
  area, retain the existing overlay code for the token line/retry rail. The range
  buttons (15m/1h/6h/24h) and the per-category footer legend stay as-is.
- Keep the `compact` prop → just changes `className` height + chrome.

### (b) Context Ring → Tremor `ProgressCircle` (preferred) or `DonutChart`

The Context gauge is a single-value % ring with centered text — that's
**`ProgressCircle`**, not DonutChart (DonutChart is for part-to-whole multi-slice
data; overkill for one %). The current `Ring` already takes `pct: number | null`.

```tsx
import { ProgressCircle } from "../components/ProgressCircle"; // copied-in

<ProgressCircle
  value={ctxPct ?? 0}
  radius={16}            // matches today's r≈14 + 4px stroke at 36px box
  strokeWidth={4}
  variant={ctxPct != null && ctxPct >= 80 ? "error" : "default"}
>
  {/* center label optional; today the % sits beside the ring, so render none */}
</ProgressCircle>
```

Map `variant` colors in the copied component: `default` → `--color-chart-1` /
`--primary`, `error` → `--destructive`, unfilled track →
`text-muted-foreground/20`. This 1:1 reproduces the existing Ring (including the
`>= 80% turns destructive` behavior) while gaining a cleaner, maintained
implementation. The surrounding `StatCard`, `%` text, token-count subline, and
the `ContextBreakdownBar` stacked mini-bar are unrelated — **leave them
hand-rolled** (the breakdown bar is a flex bar, not a Tremor chart).

## 6. Recommended install / setup steps for THIS repo

Repo: `ui/` = Vite + React 19 + TS + Tailwind v4 CSS-first (`@import
"tailwindcss"` + `@theme inline`/`.dark` in `ui/src/index.css`) + shadcn (`cn()`
in `ui/src/lib/utils.ts`).

1. **Install runtime deps** (from `ui/`):
   ```bash
   cd ui && npm i recharts tailwind-variants
   ```
   (We already have `clsx`, `tailwind-merge`, `radix-ui`.)
2. **Copy in the Tremor Raw files** from tremor.so docs / the `tremorlabs/tremor`
   repo:
   - `ui/src/lib/chartUtils.ts` (the color map + `getColorClassName`)
   - `ui/src/components/AreaChart.tsx`
   - `ui/src/components/ProgressCircle.tsx`
   Use Tremor's existing `cx` or rewire imports to our `cn()` — pick one and be
   consistent. No new `lib/utils.ts` needed; reuse the repo's.
3. **Rewrite `chartUtils.ts` colors** to our tokens — replace the default
   `blue/emerald/…` entries with `chart1..chart5` mapping to
   `fill-[var(--color-chart-N)]` / `stroke-…` / `bg-…` / `text-…` (see §4). Make
   `AvailableChartColorsKeys` = `"chart1".."chart5"`.
4. **No Tailwind config changes.** v4 auto-scans `ui/src/**`, so the copied
   components' classes are picked up. (Only add an `@source` line in `index.css`
   if a class ever lives outside the scanned source — not the case here.)
5. **Migrate the two components**: reshape `usePulse` buckets → flat rows for
   `AreaChart` (§5a, keep the overlay/retry SVG + range buttons + footer legend);
   swap the `Ring` SVG for `ProgressCircle` (§5b), mapping `variant` to our
   tokens.
6. **Verify**: `cd ui && npm run build` clean (typecheck + Vite build), then
   visually check light + dark in a browser via the `automate-browser` skill —
   confirm the area bands use chart-1..5, the dark toggle reflows colors, and the
   Context ring turns destructive past 80%. Watch the build output for any
   Recharts React-19 peer warning (§3).

### If Recharts bundle cost is unacceptable
Stay hand-rolled. Our current SVGs already honor tokens, have zero deps, and are
fully under our control. Tremor's win is tooltips/legends/responsiveness/a11y for
free — judge against the ~100 KB+ gzipped Recharts cost. There is no
middle-ground "Tremor without Recharts" for these chart types.
