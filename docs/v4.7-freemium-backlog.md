# Conan v4.7 — backlog (Freemium · Free + Premium tiers)

Backlog to research → PRD → decompose → loop. Same flow as prior versions
(`docs/v4.6-backlog.md`, `docs/v4.4-backlog.md`, `docs/timeline-prd.md`).

**Companion docs:**
- [`docs/v4.7-licensing-design.md`](./v4.7-licensing-design.md) — the
  licensing lifecycle floor (token format, issuance, activation, verification,
  multi-machine, revocation, key management).
- [`docs/v4.7-update-design.md`](./v4.7-update-design.md) — the auto-update
  channel (Tauri updater plugin, minisign, manifest hosting, the release
  pipeline). Pairs with the licensing doc — updates are how revocations and
  edition migrations actually reach paying users.

Read all three before `decompose-prd`.

The product premise for this loop: **Conan stays a free, fully-functional local
observability tool**, with a small Premium tier that unlocks history depth,
ranged charts, and a watchdog for MCP auth. The cap is on the **rear-view**
(scrolling back past N days), never on the **present** (live append, current
session). Enforcement is offline-verifiable JWT licensing — the Sublime Text /
Sketch / Tower model — kept honest by good ergonomics, not DRM.

**Decision floor (informs every story below):**
- **Live data is always free.** The Timeline appends new rows for everyone; the
  cap only bites when you scroll backwards beyond the window.
- **No launch-time upgrade prompts. No banners. No popups.** A single muted
  "+ N earlier rows beyond your 7-day window" affordance at the *bottom* of the
  Timeline is the only inline ask. Locked Pulse range tabs render disabled at
  ~40% opacity with a tooltip.
- **Premium is a feature flag, not a moat.** A motivated user can patch the
  binary. That's fine — that's true of every desktop license tool.
- **Trial = 14 days** unlocked, no card needed. Driven by the JWT's `exp`.

## US-101 — Tier hook + license loader (foundation)
Every gated surface below reads a single source of truth:
`useTier()` → `'free' | 'premium' | 'trial'`. The hook reads a license file at
`~/Library/Application Support/so.whatmatters.conan/license.jwt`, verifies the
signature against a bundled Ed25519 public key, checks `exp`, and caches the
result for the session. **The crypto is offline** — no phone-home, no analytics
ping. Default tier is `free` when the file is absent / invalid / expired.

The hook must:
- Be importable from anywhere in `ui/src` without a context wrap (uses
  `useSyncExternalStore` over a module-level store, same pattern as
  `useAppearance` v4.6 US-019).
- Expose `tier`, `expiresAt?`, `daysRemaining?`, and a `reload()` action for
  the Settings ▸ License tab (US-106) to call after a paste.
- Treat a malformed token as `free` silently — never throw, never log to the
  user (a license-import error belongs in the Settings tab, not the dock).

Backend side: zero changes. The cap clauses (US-102, US-103, US-104) read tier
via the **license token sent as a header** (`x-conan-license`) on those
endpoints; without it, backend defaults to free-tier limits. This keeps the
license off the gateway's disk — it lives in the UI's localStorage cache plus
the user-data-dir file.

### Why it matters
Without this, every gated story below grows its own ad-hoc "is paid" check and
the system fragments. Ship the foundation first, leave the gates as cheap
component additions.

### Open questions (resolve at PRD time)
- Where does the **public key** live? Inlined as a base64 const in
  `ui/src/lib/license.ts` (simplest; rotating it means a UI rebuild). Or pulled
  from a tauri resource file (slightly more flexible). I'd start inline.
- Should the gateway *also* verify the JWT for the backend caps, or trust the
  header on loopback only? Loopback-trust is fine for free-tier caps (the
  attacker is the user, who has the binary anyway); for **anti-tamper**
  (preventing a free user from reaching premium-only routes that, say, hit a
  paid cloud endpoint later), the gateway verifies too.
- Trial start: count from first launch (stored in user-data-dir) so reinstalls
  don't reset. Document this — a fresh-machine install gets a fresh trial.

### Rough story breakdown (to refine in the PRD)
1. `ui/src/lib/license.ts` — JWT verifier + parser, with a tiny Ed25519
   verification (use `@noble/ed25519`, ~10kB gzipped, zero deps).
2. `ui/src/hooks/useTier.ts` — module-level store + `useSyncExternalStore` hook.
3. Backend `src/license/index.ts` — same verification for header-sent tokens
   (only used by the cap endpoints US-102/103, **not** every route).
4. Bundled Ed25519 public key + a `scripts/issue-license.mjs` dev helper that
   signs a token from your laptop for testing (your private key never lives in
   the repo — keep it in a password manager / 1Password).

### References
- `useAppearance` module-store pattern (v4.6 US-019):
  `ui/src/hooks/useAppearance.ts`.
- Tauri data dir resolution: already wired via `CONAN_DATA_DIR` env from
  `src-tauri/src/lib.rs` (the same dir that holds `auth-token` and
  `active-cwd`).
- JWT EdDSA: `@noble/ed25519` (MIT, ~10kB).

## US-102 — Timeline cap (7 days / 200 rows) + the "+ N earlier" affordance
The Timeline split panel (v4.5-timeline US-001..007) currently reads all rows
for a session via `GET /api/claude/timeline?session=…&since=…&limit=…`. For
Free tier, cap the **history window** so a user scrolling backwards stops at
either **7 days** OR **200 rows**, whichever is *more inclusive* (most sessions
are way under 200 rows in 7 days). Premium has no cap.

**The cap only bites going backwards.** Live append continues unconditionally
for both tiers — the WS broadcasts (`{type:'event'}`, `{type:'skill-fired'}`,
`{type:'plan'}`, `{type:'tasks'}`) are never gated. A user mid-task always
sees the row they're producing right now.

**The affordance.** When the scroll reaches the bottom of the capped slice and
there are more rows on the server side, render one sticky row at the bottom:

```
+ 247 earlier rows beyond your 7-day window         Premium ↗
```

Muted styling (`text-muted-foreground`), single line, no icon spam. Clicking
**Premium ↗** opens the in-app Settings ▸ License tab (US-106), not an external
page. No popup, no banner, no launch-time prompt.

### Why it matters
Timeline is the marquee surface for v0.2 — capping it tastefully sets the tone
for the whole freemium model. Done badly, this is the feature users will
remember; done well, they'll barely notice (most sessions don't exceed the cap).

### Open questions (resolve at PRD time)
- Does the cap count from **now**, or from **session start**? The "7-day"
  framing is from now (rolling window), which feels right for the audit-trail
  use case. Per-session caps from start would be confusing for long-running
  loops.
- 200 rows OR 7 days — what's the OR logic? Server returns
  `max(rows in 7 days, last 200 rows)`. So a chatty 3-day session returning 350
  rows shows all 350; a quiet 30-day session shows the last 200.
- Should the affordance show the *count* of hidden rows (requires a second
  query)? Probably yes — the number is the honest signal of what you're
  missing. Use `COUNT(*)` over the full session.

### Rough story breakdown (to refine in the PRD)
1. Backend: `src/timeline/index.ts` `readTimeline()` gains an optional
   `tier` arg defaulting to `free`; `free` adds the WHERE clause
   `ts > now - 7d AND rowid > (max_rowid - 200)`. Returns a
   `cappedTotal` field with the full count.
2. Gateway route reads `x-conan-license` header → tier → passes to readTimeline.
3. UI: `Timeline.tsx` reads `useTier()`; renders the sticky "+ N earlier rows"
   row when `cappedTotal > rows.length && tier === 'free'`. Click opens
   Settings ▸ License.
4. UI: `Timeline.tsx` live-append path stays untouched — WS adds rows on top,
   never blocked.

### References
- Read endpoint: `GET /api/claude/timeline` in `src/gateway/index.ts`, backed
  by `readTimeline` in `src/timeline/index.ts`.
- Timeline UI: `ui/src/components/Timeline.tsx` (v4.5-timeline US-004).
- WS append broadcasts in `useGateway` (`ui/src/hooks/useTasks.ts`).

## US-103 — Pulse range cap (15m · 1h free; 6h · 24h · 7d premium)
The Pulse tab (v4.4 US-005, v4.6 US-001/005) currently exposes 4 ranges
(15m / 1h / 6h / 24h) via the secondary toolbar's `<PulseRange>` selector.
Free tier sees only **15m** and **1h**; **6h, 24h, 7d** are premium.

**Render the locked tabs at ~40% opacity** with a tooltip
("6h pulse · Premium") — *not* hidden, so the user sees what they don't have.
Clicking a locked tab opens Settings ▸ License.

Also: add a **`7d`** range option (premium-only) that doesn't exist today.
That's the single ranged feature that justifies the upgrade for power users.

### Why it matters
Cheap to ship, high signal: a power user opens Pulse, sees `24h` locked,
understands the value prop instantly. The disabled state is honest — no
hiding, no fake "loading" — and the 7d range is the actual carrot for users
who want a multi-day usage view.

### Open questions (resolve at PRD time)
- Does 7d Pulse need backend changes? Currently `pulseSeries(minutes)` is
  range-flexible — should already work at `60 * 24 * 7`. Verify the bucket
  arithmetic doesn't go funny at that size; might need a coarser bucket.
- Should the disabled range still **render a faded preview chart** if the user
  hovers the locked tab? Probably no for v0 — just the tooltip. Future polish.

### Rough story breakdown (to refine in the PRD)
1. UI: `<PulseRange>` component reads `useTier()`; renders 6h/24h/7d as
   `disabled` for free, with a tooltip. Click opens Settings ▸ License.
2. Backend: verify `pulseSeries(60 * 24 * 7)` produces a usable series (likely
   needs a bucket size bump from per-minute to per-15m for the 7d range).
3. Cap enforcement at the route: `GET /api/claude/pulse?minutes=N` rejects
   `minutes > 60` for free-tier license headers (defense-in-depth — UI gates
   visually, server enforces).

### References
- Pulse UI: `ui/src/components/PulseChart.tsx`, range toolbar in `Hud.tsx`
  (v4.6 US-005).
- Backend: `src/pulse/index.ts` `pulseSeries()`.

## US-104 — Skills `last fired` history (free = today; premium = full)
The Skills tab (v4.3 US-006 + v4.5 `lastFiredAt`) shows `last fired Xm ago`
when the transcript scanner found a recent `Skill` tool_use. Free tier shows
this only when the firing was **today (last 24h)**; older firings are hidden.
Premium shows them indefinitely (e.g. `last fired 12d ago`).

This is a tiny ergonomic cap, but it differentiates the tab: a user reviewing
"have I ever actually used this skill" sees that information only in Premium.
Free still gets "did this skill fire today" — useful for the *now* loop.

### Why it matters
Cheap, low-friction, and reinforces the "current = free, history = premium"
pattern. The Skills tab becomes a *retrospective tool* for paid users and a
*live tool* for free users.

### Open questions (resolve at PRD time)
- Where's the cap applied — backend (`readSkills` filters) or UI (always
  fetches all, hides at render time)? Backend is cleaner; UI is faster to ship
  (no API change). I'd do backend — keeps the data minimal.

### Rough story breakdown
1. Backend `readSkills(opts: { tier })` — when free, only `lastFiredAt` rows
   within 24h are returned populated; older firings come back as `null`.
2. UI: `SkillsWidget.tsx` already handles `lastFiredAt == null` — no change.

### References
- Skills surface: `ui/src/components/SkillsWidget.tsx`,
  `ui/src/hooks/useSkills.ts`.
- Backend: `src/skills/index.ts` `readSkills()`, `lastFiredAt` from
  `src/timeline/transcriptScan.ts`.

## US-105 — MCP auth watchdog (Premium-only background reconnect)
v4.6 US-014 shipped manual **Authenticate / Reconnect** buttons on the MCP tab.
Premium tier adds a **background watchdog** that:
- Periodically polls `claude mcp list` (cache-bypass) every ~5 minutes.
- When a `connected` server flips to `needs-authentication` / `failed`, fires
  a native macOS notification (`MCP server "X" needs reconnection`) and offers
  one-click reconnect from the banner.
- Optionally (settable in Settings ▸ License): automatically runs Reconnect
  for `failed` rows, escalates to Authenticate for `needs-authentication` rows.
  Off by default — the proactive notification is enough for most users; full
  auto-reconnect needs an opt-in.

### Why it matters
MCP auth expires regularly; for users with many connected servers (research
flow, multi-tool agents), the watchdog is real, recurring value. This is the
classic "ongoing automation = paid" axis — a tier model that ages well.

### Open questions (resolve at PRD time)
- Polling interval: 5 min is conservative; 1 min may be appropriate but burns
  the throwaway pty more often. Settable in Settings?
- "Auto-reconnect failed" — does the user authorize each Authenticate
  individually (browser OAuth prompts anyway), or is the toggle a blanket
  pre-authorization? OAuth always requires a browser flow, so this can never
  be silent for `needs-authentication`; for plain `failed`, the watchdog can
  silently re-health-check + escalate only if the diagnosis is auth.
- Notification fatigue: throttle by `{server name, minute bucket}` so a
  flapping server doesn't spam — same THROTTLE pattern as
  `useNativeNotifications` (v4.4 US-011).

### Rough story breakdown
1. Backend: `src/mcp/watchdog.ts` — interval timer, gated by a `--premium`
   boot flag (read from the same license file the UI uses).
2. Gateway: a `{type:'mcp-change'}` WS broadcast for any status flip detected
   by the watchdog; UI listens, shows the row's pending state immediately.
3. UI: `useNativeNotifications.ts` gains an effect for the new broadcast,
   throttled per-server.
4. Settings ▸ License tab gets a toggle: "Auto-reconnect failed MCP servers"
   (default off).

### References
- MCP backend: `src/mcp/index.ts` `getMcpServers()`, `src/mcp/auth.ts`
  `startMcpAuth()` / `reconnectMcp()` (v4.6 US-011..013).
- MCP UI: `ui/src/components/McpWidget.tsx`, `ui/src/hooks/useMcp.ts` (v4.6
  US-014).

## US-106 — Settings ▸ License tab
A new tab in the Settings dialog (v4.4 US-009/010 + v4.6 US-015..017) named
**License**, sitting alongside **Status · Config · Appearance**. Contents:

- **Current tier**: `Free` / `Trial · N days left` / `Premium · expires YYYY-MM-DD`.
- **License key field** — paste a JWT, click **Apply**. On success, the field
  clears and the tier banner updates. On failure, inline error
  ("Invalid license · expired" / "Invalid license · signature").
- **Buy Premium** button — opens an external URL (Stripe checkout page hosted
  outside the app). Honest copy: "Opens your browser to complete purchase. The
  license token will be emailed to you."
- **What's included** — short bullet list mirroring the cap table from this
  backlog (Timeline retention, Pulse range, Skills history, MCP watchdog).
- **What stays free** — explicit bullet list, so users on the fence
  understand the local tool isn't crippled.

### Why it matters
This is the one place upgrade lives. Everywhere else, the "Premium ↗" affordance
deep-links here. No paywall modal anywhere else in the app.

### Open questions (resolve at PRD time)
- Buy URL: hardcoded to `https://conan.whatmatters.so/buy` or fetched from
  a config endpoint? Hardcoded is simpler; fetched lets you A/B the funnel.
- Should we show a license **fingerprint** (e.g. last 8 chars) so users can
  identify which token is active across devices? Probably yes — minimal effort,
  helps support.
- Refund / re-issue flow: out of scope for the build loop, but document the
  Stripe → email → token-regen path in the README before launch.

### Rough story breakdown
1. UI: `ui/src/components/SettingsView.tsx` gets a `<TabsTrigger value="license">`
   and a `<TabsContent>`. Reuses the v4.6 US-015 flat tab style.
2. The tier banner reads from `useTier()` (US-101); the paste action calls
   `applyLicense(jwt)` which writes the file and calls `reload()`.
3. The cap/feature lists live in a single source-of-truth constant
   `ui/src/lib/tierFeatures.ts` so the same copy renders in the Settings tab
   AND any tooltip on a disabled control (US-103's Pulse range tooltip).

### References
- Settings shell: `ui/src/components/SettingsView.tsx` (v4.4 US-009/010 +
  v4.6 US-015/016/017).
- Shared tab styles: `ui/src/lib/tabStyles.ts` (v4.6 US-015).

## US-107 — License issuance pipeline (out-of-loop infra, but documented)
**This story doesn't ship code in the Conan repo** — it's the receipt-side
infrastructure that issues the JWT after a Polar.sh order. Out-of-loop because
it lives in a separate small Vercel project, not in the Conan binary. But
documenting it here so the freemium loop ships with the *complete* picture,
not a UI for a license that nobody can buy.

**Processor: Polar.sh** (decided 2026-05-29 — see licensing-design §1, §2).
Merchant of Record so we don't owe global VAT/GST; 4% + $0.40 per transaction;
hosted checkout + receipt email handled by Polar; chargebacks absorbed by them.
~30% lighter than the equivalent Stripe + Resend pipeline.

The shape:
- **Vercel function** at `https://conan.whatmatters.so/api/polar-webhook`
  receives `order.created` from Polar.
- It signs a JWT with the private Ed25519 key (held in Vercel env), bound to
  the customer's email + a `sub` (license id), with `exp` 1 year from purchase.
- Writes the JWT back to the Polar order metadata; Polar's receipt email
  template variable `{{order.metadata.license}}` renders it to the customer.
- A second handler watches `order.refunded` → auto-revoke.
- Polar webhook secret + private signing key in Vercel env; **never** in the
  Conan repo.

### Why it matters
Without this, US-106's Buy button is a dead end. Treat this as the rest of the
launch checklist — it has to exist before any of US-101..106 land in a release.

### Rough story breakdown
1. Spin up `conan-license/` repo (separate). Vercel function + Polar webhook
   handlers. ~80 LoC total (down from ~150 with Stripe+Resend).
2. Configure Polar product ($39/yr), receipt email template, hosted checkout
   URL.
3. Document the issue-license flow in `docs/freemium-issuance.md` in *this*
   repo so future you / a collaborator can find it.
4. Test the round-trip: order via Polar test mode → receive token email →
   paste in Settings ▸ License → tier flips to `Premium`.

### References
- Licensing-design §1-§3 — Polar lifecycle + webhook handler + email template.
- The dev helper `scripts/issue-license.mjs` (US-101) is the local equivalent
  of the Vercel function — same signing call, different input source.
- Polar docs: `https://docs.polar.sh/integrations/webhooks/intro`.

## Cross-cutting design rules (read before any story)

1. **Live data is never gated.** Every WS broadcast, every `current` value,
   every refresh button works identically on Free and Premium.
2. **The cap is on history.** Free = today / last 7 days / last 200 rows.
3. **No interrupt UX.** No upgrade modal that blocks the app. The affordances
   are inline, muted, single-line, and deep-link to Settings ▸ License.
4. **Locked controls are visible but disabled.** `~40% opacity + tooltip`. The
   user sees what they don't have — this builds trust and clarity.
5. **License loader is offline-only.** Zero network calls from the app for
   license verification. The JWT is verified locally against a bundled
   public key. (Issuance is online; verification is not.)
6. **Free tier must remain genuinely useful.** If a user pays nothing and
   doesn't feel crippled, your conversion happens when they hit a *specific*
   need (multi-day pulse, MCP watchdog, full timeline) — not because they're
   frustrated.

## Open product decisions

**Locked 2026-05-29:**
- ✅ **Processor: Polar.sh.** Merchant of Record. 4% + $0.40 per transaction.
- ✅ **Price: $39/year** (default annual one-time, revisit subscription at
  Polar setup).

**Still open (resolve before decompose-prd):**
1. **Trial duration.** 14 days proposed; should it be longer (30) so users
   hit the cap organically? Less is more friction-honest; more converts
   better.
2. **Refund window.** 7 days no-questions proposed — Polar's customer
   portal handles the mechanics.
3. **Subscription vs one-time annual.** Default to one-time at $39 (friendlier
   at this price point). Revisit if churn analysis later argues for
   auto-renew.
4. **Team / org licensing.** Out of scope for v0.2 — single-user only. Tag
   as v0.3+ once we know whether users actually share machines.
