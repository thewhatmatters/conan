# Conan v4.1 research — Tauri v2 native desktop app (gateway-as-sidecar)

Implementation guide for wrapping the existing React + xterm.js UI + Node gateway as a
Tauri v2 desktop app, with the gateway running as a Tauri **sidecar** (externalBin) the
webview connects to on loopback `127.0.0.1:3747` exactly as the browser does today.
(Research agent output, 2026-05-26.)

## Repo facts that anchor this
- Gateway entry: `src/gateway/index.ts`, `server.listen(PORT, HOST)` with
  `PORT = process.env.CONAN_PORT ?? 3747`.
- Token + config: `GET /api/config` returns `{ token, port, cwd }`.
- WS Origin allowlist: `src/gateway/auth.ts` — `allowedOrigins()` defaults to
  `http://127.0.0.1:3747`, `http://localhost:3747`, `:5173`; extendable via
  `CONAN_ALLOWED_ORIGINS`.
- UI fetches **same-origin** `/api/config` + `/api/health` in `ui/src/App.tsx`; the token
  flows into the terminal WS (`ui/src/components/Terminal.tsx`).
- Native deps: `better-sqlite3`, `node-pty` (node-pty needs `scripts/fix-node-pty.mjs` to
  fix its `spawn-helper` perms — the crux of the packaging risk).

## 1. Add Tauri v2 to the existing Vite + React app
`src-tauri/` lives at the **repo root** (next to `ui/`, not inside it).

```bash
npm install -D @tauri-apps/cli@latest
npm install @tauri-apps/api@^2 @tauri-apps/plugin-shell@^2
npx tauri init
```
`tauri init` answers: frontend dev URL `http://localhost:5173`; dist dir `../ui/dist`;
before-dev `npm --prefix ui run dev`; before-build `npm --prefix ui run build`.

`tauri.conf.json` (v2 schema — `build` keys are `devUrl`/`frontendDist`, NOT v1
`devPath`/`distDir`):
```json
{
  "$schema": "https://schema.tauri.app/config/2",
  "productName": "Conan",
  "version": "0.1.0",
  "identifier": "so.whatmatters.conan",
  "build": {
    "beforeDevCommand": "npm --prefix ui run dev",
    "beforeBuildCommand": "npm --prefix ui run build",
    "devUrl": "http://localhost:5173",
    "frontendDist": "../ui/dist"
  },
  "app": {
    "windows": [{ "title": "Conan", "width": 1400, "height": 900 }],
    "security": { "csp": null }
  },
  "bundle": {
    "active": true,
    "targets": ["app", "dmg"],
    "externalBin": ["binaries/conan-gateway"]
  }
}
```
Run with `npx tauri dev` / `npx tauri build`. Set Vite to a fixed port + `clearScreen:
false`.

## 2. Sidecar (externalBin) — bundling + spawning
- `bundle.externalBin: ["binaries/conan-gateway"]` (path relative to `src-tauri/`).
- **Target-triple suffix is mandatory:** the file on disk must be
  `conan-gateway-<TARGET_TRIPLE>` — on Apple Silicon
  `src-tauri/binaries/conan-gateway-aarch64-apple-darwin`. Find the triple with
  `rustc -Vv | grep host` (or `rustc --print host-tuple`). Tauri strips the triple at
  bundle time; a mismatch yields a runtime `Io NotFound`.
- **Capability** (`src-tauri/capabilities/default.json`):
```json
{
  "identifier": "default",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "shell:default",
    { "identifier": "shell:allow-spawn",
      "allow": [{ "name": "binaries/conan-gateway", "sidecar": true, "args": true }] }
  ]
}
```
  Add `tauri-plugin-shell = "2"` to `Cargo.toml` and `.plugin(tauri_plugin_shell::init())`
  in `lib.rs`.
- **Spawn on startup + kill on exit (Rust, `src-tauri/src/lib.rs`):** spawn in the
  `setup` hook, hold the `CommandChild` in Tauri state, kill it on `RunEvent::
  ExitRequested`. Pass `CONAN_PORT` (and `CONAN_ALLOWED_ORIGINS`) via `.env()`. A clean
  `child.kill()` matters — the gateway is single-instance on :3747 and refuses to start
  if the port is bound, so a leaked sidecar blocks the next launch. Consider a
  stdin-EOF watchdog in the gateway as belt-and-suspenders.

## 3. Packaging the Node gateway into a sidecar binary — THE HARD PART
Native `.node` addons **cannot be embedded into a VM-snapshot/bytecode binary** — every
single-binary tool ships them as files on disk next to the executable.

Options:
- **(a) Node SEA** — must list addons in SEA `assets` and manually rewrite how
  better-sqlite3/node-pty locate their `.node` (write to temp + `process.dlopen`). Lots
  of fragile plumbing. **Not recommended.**
- **(b) `@yao-pkg/pkg`** (maintained fork; vercel/pkg archived) — detects native addons,
  leaves them as external files, extracts/loads them next to the exe at runtime. macOS
  arm64 is **experimental** and the binary **must be code-signed** (ad-hoc ok). Most
  battle-tested route for node-pty + better-sqlite3; the path Tauri's own "Node.js as a
  sidecar" doc uses.
- **(c) `bun build --compile`** — N-API addons (not FFI) are exactly Bun's edge that
  still breaks; node-pty is risky. **Not recommended as primary.**
- **(d) Ship a bundled `node` + JS + prebuilt `node_modules` (recommended / most
  reliable)** — don't compile. esbuild the gateway to one `.js` (or ship compiled
  `src/`), copy a `node_modules` with arm64 prebuilds of better-sqlite3/node-pty, and a
  `node` binary; the sidecar is a tiny launcher (shell stub or small Rust/Go shim named
  with the target triple) that execs `node gateway.js`. Native modules load by normal
  resolution — no extraction hacks. Larger bundle, least likely to break.

**Recommended:** primary = (d) bundled-node launcher; if a true single file is wanted,
(b) `@yao-pkg/pkg` carrying the addons:
```json
"pkg": {
  "assets": [
    "node_modules/better-sqlite3/build/Release/*.node",
    "node_modules/node-pty/build/Release/*.node",
    "node_modules/node-pty/build/Release/spawn-helper"
  ],
  "targets": ["node20-macos-arm64"]
}
```

### Native-module gotchas (real risk)
- **Match the Node version** used to package to the version the `.node` files were
  compiled against (ABI) — mismatch = runtime load failure.
- **`better-sqlite3`** ships `better_sqlite3.node` under `build/Release/`; verify it
  actually travels (classic pkg failure is silent omission).
- **`node-pty` `spawn-helper`** is the sharp edge: a separate executable that ships
  non-executable. Must (1) include it as an asset AND (2) keep the **+x bit** after
  extraction — pkg often drops it → `posix_spawnp failed`. Likely need a runtime
  `chmod +x`, or use approach (d) where the file tree preserves perms.
- **arm64 all the way:** verify `aarch64` prebuilds; pkg/node target must be
  `macos-arm64`.
- **Codesign the sidecar binary itself** (not just the .app) or Gatekeeper/kernel kills
  it. Tauri signs externalBins during bundling when an identity is set; known ordering
  issue (tauri#11992) with externalBin + notarization — test the notarized build E2E.

**Bottom line:** budget real time for native-module packaging. Validate on a clean
machine (no global Node): open a DB (better-sqlite3) + open a terminal (node-pty →
spawn-helper). These are the two things most likely to fail post-bundle.

## 4. Webview ↔ sidecar wiring + security
- **Webview origin:** production macOS = `tauri://localhost`; `tauri dev` = the Vite
  `http://localhost:5173`. (Windows/Android use `https://tauri.localhost`.)
- **WS Origin allowlist (required):** add the Tauri origins or the WS upgrade is
  rejected. Simplest: spawn the sidecar with
  `CONAN_ALLOWED_ORIGINS=tauri://localhost,http://tauri.localhost,https://tauri.localhost`
  (`http://localhost:5173` is already a default). The webview DOES send `Origin:
  tauri://localhost` on WS connect, so `verifyUpgradeOrigin` must find it.
- **CSP:** keep `"csp": null` (simplest, acceptable for loopback desktop) or set
  `connect-src 'self' http://127.0.0.1:3747 ws://127.0.0.1:3747 http://localhost:3747
  ws://localhost:3747`. macOS allows the `tauri://localhost` page to reach plaintext
  loopback http/ws (no mixed-content block).
- **Port/token discovery — the wiring that must change:** today the UI does same-origin
  `fetch('/api/config')`/WS. Under Tauri the UI origin (`tauri://localhost`) ≠ the
  gateway origin, so relative fetches fail. Two fixes:
  1. Make API/WS URLs **absolute to the gateway** — `const GATEWAY =
     'http://127.0.0.1:3747'`; gate on `import.meta.env` or detect Tauri
     (`'__TAURI_INTERNALS__' in window`). In browser dev (`:5173`) the Vite proxy still
     works.
  2. `/api/config` still returns the token; cross-origin `fetch` to `127.0.0.1:3747`
     works in the Tauri webview (not bound by browser CORS the way a remote page is).
     Pin `CONAN_PORT=3747` via the sidecar env so the hard-coded base is safe; if a
     dynamic port is ever needed, have the sidecar print it on stdout and pass it to the
     webview via a Tauri command/event.
- **CORS:** if a browser-style CORS block appears on `/api/config`, add
  `Access-Control-Allow-Origin: tauri://localhost` or use Tauri's `http` plugin.

## 5. macOS bundling
- `bundle.targets: ["app", "dmg"]` → `Conan.app` + `.dmg` under
  `src-tauri/target/release/bundle/{macos,dmg}/`.
- **Local dev:** no signing/notarization needed for the .app — BUT the **sidecar binary**
  may need an **ad-hoc signature** on arm64 (`codesign -s - <binary>`) or the kernel
  kills pkg-built binaries.
- **Distribution:** requires a paid Apple Developer ID — code-sign + notarize, or users
  get "unverified/damaged". Test the notarized build E2E (the embedded gateway must be
  signed and still spawn after Gatekeeper validation).

## Recommended order of operations
1. `tauri init` at repo root; wire `tauri.conf.json` build keys to `ui/`.
2. Build the gateway sidecar (approach (d) or `@yao-pkg/pkg`); name it
   `conan-gateway-aarch64-apple-darwin`; **prove better-sqlite3 + node-pty/spawn-helper
   work from the packaged binary on a clean machine** — this is the gate.
3. Add `externalBin`, shell plugin + `shell:allow-spawn`, Rust spawn/kill.
4. Add Tauri origins to the Origin allowlist (sidecar env); set CSP `connect-src`.
5. Change the UI to an absolute gateway base, Tauri-detected.
6. `tauri build` → `.app`/`.dmg`; ad-hoc sign the sidecar locally; full Developer-ID
   sign + notarize for distribution.

**Biggest risk, restated:** native-module packaging (step 2) — `node-pty`'s
`spawn-helper` losing +x after extraction, ABI/arch mismatches, the sidecar needing a
signature on arm64. Everything else (origins, CSP, port/token rewiring) is mechanical.
