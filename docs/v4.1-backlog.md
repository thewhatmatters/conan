# Conan v4.1 — Tauri terminal wrapper for Claude Code ("beefed-up TUI")

Backlog to research → PRD → decompose → loop. Same flow as prior versions.

## The pivot (decided 2026-05-26)
Conan becomes a **terminal-primary desktop app** that wraps Claude Code with an
at-a-glance **widget HUD** — not a sprawling web dashboard. **No activity-timeline
page, no Agents/Skills/Settings nav.** Just the Claude Code terminal + a tabbed widget
panel (DevTools-style tabs), shipped as a **native desktop app via Tauri** (going
straight to "option B" — skip the simplify-the-web-app-first step).

## Why Tauri (not Zig/Ghostty-native, not Electron)
- Reuse the **existing React + xterm.js UI + Node gateway** (PTY, `/api/claude/*`,
  hooks, SQLite) — no rewrite of the core.
- Tauri = Rust core + the OS's **native webview** (small/fast; NOT bundled Chromium like
  Electron) → a real standalone window — the "it's an app, not a browser tab" feel.
- A Claude Code wrapper is **not terminal-perf-bound**, so Ghostty's Zig + Metal/GTK
  stack is unnecessary. (Ghostty = libghostty in **Zig** + native UI: Swift/AppKit+Metal
  on macOS, GTK4+OpenGL on Linux; GPU-accelerated, not Electron.) **xterm.js** — the
  renderer VS Code ships, already in Conan — is plenty here.

## Initial scope (start small)
- **Terminal** (xterm + node-pty) as the primary surface; keep the `Term ▾` dropdown.
- **Pulse graph** — the existing `PulseChart` (global activity time-series).
- **Widget HUD — exactly 2 widgets to start, DevTools-style tabs:**
  1. **Context** — *session-scoped* (the active session's context %); existing `ContextWidget`.
  2. **Usage** — *global* (plan-usage approximation); existing `UsageWidget`.
- Everything else (MCP, Model, Git, Stats, per-project metrics, the Sessions timeline,
  the Agents/Skills/Settings pages) is **cut from the initial cut**. Some may return as
  widget tabs later — decide per-widget, don't auto-port.

## Tauri research / open questions (for the PRD)
- **PTY model — DECIDED: Node gateway as a Tauri sidecar.** Tauri bundles + spawns the
  existing Express+ws+node-pty gateway; the webview connects to it on loopback exactly
  as today. **Rationale:** the gateway isn't just the PTY — it's the data source for the
  three starting surfaces (Context, Usage, Pulse all come from `/api/claude/*`), plus
  session tracking, hooks, and SQLite. Since we need the gateway regardless, running the
  terminal through it too means near-zero rewrite. *(Rejected: Rust `portable-pty` —
  would rewrite the terminal AND still need the Node gateway for the widget data, so it
  adds processes for no near-term gain. Revisit only if going fully native later.)*
  Trade-off accepted: ships a Node runtime in the bundle + needs `node-pty` packaged
  carefully (the spawn-helper footgun).
- **Auth/Origin:** the Tauri webview origin is `tauri://localhost` (mac) / similar — add it
  to the gateway's Origin allowlist (`src/gateway/auth.ts`), or trust the loopback sidecar.
- **Packaging:** Tauri bundler (`.app`/`.dmg`); how the gateway sidecar binary is produced
  (node-sea / bun / pkg of the TS gateway) and shipped inside the app.
- **Window/UX:** single window, terminal-primary, widget panel docked (right or bottom)
  with DevTools-style tabs; pick the split + persistence.
- **Gateway trim:** keep PTY + the `/api/claude/*` the 3 surfaces need (Context from
  transcript usage, Usage from US-004, Pulse from `/api/claude/pulse`); the rest of the
  gateway can stay (harmless) or be trimmed later.

## What this discards
Most of the v2/v3 IA (sidebar nav, timeline-primary Overview, Agents/Skills/Settings
pages, most widgets). A deliberate, large subtraction toward a sharper product. Kept
conceptually as "could return as a widget tab."
