## AC

1. Pipeline tab uses a horizontal layered layout, not a freeform physics graph.
2. Nodes = tasks; agent/role is secondary metadata.
3. Edge/lane kinds are distinguishable without color alone.
4. States: queued, running, complete, approval, blocked, failed, skipped — each with icon + shape + label.
5. Selecting a node drives the same inspector as Overview (C3).
6. Reduced-motion safe; only running state receives subtle activity motion.
7. Narrow width fallback: show Overview list + full-height task detail; do not shrink the pipeline into a mini-map.
8. Verify against `thewhatmatters/sagan` @ `ab2cb8d`.

## Decisions

- **Stage mapping is resolved LAST-STAGE-FIRST over substrings, and Build is the
  default.** Ledger lanes and phases are open strings — `projectLedger` says
  "Never an enum", and the reference ledger already carries a `design` lane with
  no role file. Checking Promote → Verify → Critique → Build means a run that has
  reached the gate is not dragged back by a stale lane, and an unrecognised lane
  is treated as work in progress rather than dropped off the board. A pipeline
  that silently loses a task is the one failure mode this surface must not have.
- **Only a `promote*` gate moves a run's STAGE; every open gate changes its
  STATE.** `openDecisions` is the Needs-you predicate, but the reference ledger's
  `art-direction-approval` gate fires mid-build — pinning it to the Promote Gate
  column would misreport where the work is. So a non-promote gate leaves the run
  in its lane's stage with state `approval`.
- **Both edge kinds are drawn on every gap, not just where rework happened.**
  Sagan can return work from any gate — WHA-130 is on round 3 because a human
  answered the *promote* gate `revise` — so the return path is a property of the
  loop, not of the current data. Drawing it conditionally would make the board's
  shape change under the user for no gained truth.
- **`queued` / `complete` reuse the Overview's exact-match vocabulary.** A run
  must not read "Queued" in one tab and "Running" in the other, so the two
  surfaces share the same word lists rather than each inventing a heuristic.
- **The narrow fallback is measured on the pane, not the viewport.** The Sagan
  surface is resizable and can be docked beside Chat, so a media query would
  answer the wrong question. Width 0 (pre-layout, or jsdom) is treated as
  UNMEASURED rather than narrow, so the board is the default and only a real
  measurement takes it away.
- **The pulse lives in `tokens.css`, not in StyleX.** It reuses the sidebar's
  `conan-status-pulse` keyframe so the shell has one rhythm, and — more
  importantly — one `prefers-reduced-motion` block that turns every animation off
  in a single place.
- **Tabs, not a SegmentedControl.** Astryx's own guidance puts view switching on
  `TabList` and reserves `SegmentedControl` for input; the AC calls this a tab.
