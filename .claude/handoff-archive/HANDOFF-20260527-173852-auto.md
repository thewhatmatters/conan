Solve the "why did /context fire?" confusion by either (a) compute the breakdown ourselves and drop the inject, or (b) bracket the inject in the VT alt-screen buffer (`?1049h/l`) — only (b) needs a spike.
4. **cwd/branch/gateway chrome** — always-visible orientation. **OPEN DECISION A/B:** (A) fixed ASCII-banner header vs (B) slim bottom status bar (recommended; also consolidates the gateway chip out of the HUD). cwd is the must-have.

8. **Context-pressure action bar** — conditional bottom bar in a HUD tab (Context first, trigger `ctxPct >= ~80%`): Cancel + Compact. **Compact injects `/handoff`(+`/compact`) into the correlated pty** — Conan can't author the handoff itself. **DECIDED: write HANDOFF.md, not CLAUDE.md.**
9. **Settings feature** — top-level Conan ▸ Settings (`⌘,`) mirroring Claude's `/config`. **Read-only first** (disk `~/.claude/settings.json` + `~/.claude.json`, or pty-capture); editing is a risky later phase (key mapping + running-claude reload unknown). Largest/most ambiguous item.
10. **Flush UI lift** — Context/Usage content should be flush/panel-native (no card chrome), like the Pulse `compact` rule + Linear's panel; no border radius. Unify all HUD tabs.

(File order in the doc differs from this list; each item has a "Rough story breakdown" + a References pointer block at the bottom.)

## Decisions made (and why)
- **HANDOFF.md over CLAUDE.md** for the Compact action — CLAUDE.md auto-loads into every future session, so session-state there bloats/pollutes permanently; HANDOFF.md is the read-once checkpoint.
- **Hidden-window /context ruled out** by reasoning (not research) — saves a spike.
- **Bottom status bar (B) recommended** for the chrome, since it also lets us pull the gateway chip out of the HUD.
- **Settings read-only first** — editing needs the row→file→key mapping + reload behavior researched.
- The **1M-context window fix works** — verified live: this session is `claude-opus-4-7[1m]`, `/context` shows ~20% on a 1M window where a 200k default would've shown ~99%.
